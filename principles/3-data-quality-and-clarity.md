# (4) Use and present high-quality data

Consider how to uphold data integrity at every stage of the product lifecycle from proposal development and design through to prototyping and delivery. This is particularly important when the tool you're designing collects, analyses, integrates or visualises data such as data dashboards.

This is key to promoting trust and integrity in your product and organisation.

* ​Check data against core quality standards including: completeness, accuracy, consistency, uniqueness, timeliness, and relevance
* ​Ensure high data quality in all phases of the data pipeline: collection, use, analysis and presentation
* Only collect the data you need
* ​Document metadata alongside every dataset. Ensure that data sources and collection methods are transparent and well-documented, so others can trace where the data came from and how it was gathered
* ​Actively check for errors, inconsistencies and bias
* ​Present data in clear, accessible formats that are easy for users to understand, regardless of technical expertise.

{% hint style="info" icon="file-shield" %}
How to responsibly use and safely store user privacy data is more explicitly addressed in the next principle: [Employ strong security practices to safeguard user data](4-protect-user-data.md)
{% endhint %}

**Questions to ask yourself**&#x20;

* Are we collecting only the data strictly necessary for the core function of the tool?
* Is our data dictionary standardised so that different departments or systems interpret the data the same way?
* Is our "clean" dataset actually hiding messy realities? (null values etc.)?
